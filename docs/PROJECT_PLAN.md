# 企画書：パークさんぽガイド（仮称）

最終更新：2026-10-26

---

## 1. 概要

東京ディズニーリゾートのパーク内を歩いていると、GPSで現在地を判定し、近くのエリアやアトラクションの**バックグラウンドストーリー（BGS）・小ネタ・隠れミッキーのヒント**を表示してくれる、非公式のガイドWebサイト。

- 形態：スマホ向けWebサイト（PWA）。アプリストアには出さない
- 公開：GitHub Pages（無料・https）
- 位置づけ：**非公式ファンサイト**。運営会社とは無関係であることを明記する

## 2. 目的とターゲット

- **目的**：パークを歩くだけで「知らなかった裏話」に出会える体験をつくる
- **ターゲット**：パークの世界観をもっと深く楽しみたいファン。BGSを調べるのが好きな人から、初めて来た人まで
- **価値の中心**：技術よりも**ネタの正確さと質**。間違いのない情報と、「公式設定」と「諸説あり」の区別が信頼につながる

## 3. 機能

### 3-1. 実装済み（試作版）

| 機能 | 内容 |
|---|---|
| 地図表示 | Leaflet＋OpenStreetMap。スポットを色分けした円で表示 |
| デモモード | 地図をタップした場所を現在地とみなす（家での動作確認用） |
| GPSモード | `watchPosition` で現在地を追跡。httpsでのみ動作 |
| 接近判定 | スポットの半径内に**新しく入ったとき**だけカード表示。半径＋10m離れるまで再通知しない |
| カード表示 | カテゴリ（裏設定／隠れミッキー／小ネタ）と情報源（公式設定／諸説あり）のバッジ付き |
| 隠れミッキー | 最初はヒントのみ表示。「見つけた！」で答えを表示し、localStorageに記録 |
| 振動 | 対応端末のみ（iPhoneのSafariは非対応） |
| 非公式表記 | 画面下部に常時表示 |

### 3-2. 次に作るもの（MVPに必要）

1. **GitHub Pagesで公開**し、スマホのGPSモードで動作確認できるようにする
2. **PWA化**：ホーム画面に追加できるようにし、アプリ本体とスポットデータをオフラインでも使えるようにする（パーク内は電波が弱い場所があるため）
3. **スポット一覧画面**：近い順に並べた一覧から、地図を見なくても読めるようにする
4. **隠れミッキーの進捗表示**：「12個中3個発見」のような表示
5. **実地テスト用のデバッグ表示**：GPSの誤差、各スポットまでの距離を表示し、ONとOFFを切り替えられるようにする

### 3-3. 将来のアイデア（MVPのあとで検討）

- エリア単位での絞り込み（ランド／シーの切り替え）
- 「公式設定」「諸説あり」の出典表示
- 読んだスポットの記録（スタンプラリー的な要素）
- 英語版
- 背景で位置を追跡したい場合はネイティブアプリ化を検討（Webでは画面を開いている間しかGPSが動かないため）

## 4. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語 | HTML / CSS / JavaScript（フレームワークなし） | 開発者が初学者のため、仕組みが見えるシンプルな構成にする |
| 地図 | Leaflet 1.9.4（unpkg CDN）＋OpenStreetMapタイル | 無料・APIキー不要 |
| 位置情報 | ブラウザのGeolocation API | アプリ審査が不要 |
| 距離計算 | ハバーサイン公式（`app.js` の `distanceMeters`） | 外部ライブラリ不要 |
| 保存 | localStorage（try/catchで囲む） | 発見済み隠れミッキーなど、端末ごとの記録用 |
| ホスティング | GitHub Pages | 無料、最初からhttps |

**注意点**
- 位置情報は https（または localhost）でしか動かない
- OpenStreetMapのタイルサーバーには利用規約がある。アクセスが増えたら別のタイル提供元への切り替えを検討する。タイルを一括で事前ダウンロードするのは規約違反なので、オフライン対応ではタイルをまとめてキャッシュしない
- 地図が表示できない状態でも、接近判定とカード表示は動くようにしておく

## 6. データ仕様（spots.js）

```js
{
  id: "hidden-1",           // 一意のID（英数字とハイフン）
  name: "スポット名",        // 画面に出る名前
  lat: 35.6318,             // 緯度
  lng: 139.8800,            // 経度
  radius: 30,               // 反応する半径（m）。目安：エリア40〜60、アトラクション30〜50
  category: "hidden",       // "bgs" | "hidden" | "trivia"
  source: "official",       // "official"（公式設定） | "theory"（諸説あり）
  hint: "ヒント文",          // category が "hidden" のときのみ
  body: "本文"              // 隠れミッキーの場合は答え
}
```

**現状のデータはすべて仮**：座標はおおよその位置で、本文は「【サンプル】」の仮テキスト。本物のネタは開発者があとで差し替える。

## 7. 権利・運用ルール（必ず守る）

- サイト名・ドメイン・アイコンに「ディズニー」「Disney」を使わない
- キャラクター画像、ロゴ、公式写真、公式サイトの文章は使わない
- 「非公式ファンサイトであり、運営会社とは無関係です」を常に表示する
- 他のサイトや書籍の文章をコピー・言い換えしない。**事実を理解したうえで自分の言葉で書く**
- 他の人が見つけた隠れミッキーや独自の考察を使う場合は出典を書く
- 公式設定とファンの推測を `source` で区別する
- 当面は広告などによる収益化をしない
- 歩きスマホを促す設計にしない（通知は短く、立ち止まって読む前提にする）

## 8. コンテンツ制作の流れ

1. 開発者が調べて、事実を短いメモにする（内容・出典）
2. AIにメモから本文を書かせる。**AIに事実を考えさせない**
3. 開発者が、メモにない情報が足されていないか確認する
4. Googleマップで座標を仮置きし、パークで実地確認して修正する
